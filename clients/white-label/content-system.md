## 07 | Protocolo de Carrossel

> Aplicar sempre que o formato for carrossel — Instagram, TikTok, LinkedIn.
> O passo de ÂNGULOS é obrigatório antes de qualquer decisão de slide.

### Etapa 1 — INPUT

Coletar antes de começar:
- **Ideia / tema** — o que o carrossel vai entregar
- **Niche / pilar** — qual pilar de conteúdo do cliente
- **Nível do funil** — TOPO / MEIO / FUNDO
- **Referência visual** *(opcional)* — print de carrossel com estilo que o cliente aprovou

### Etapa 2 — ÂNGULOS CONCEITUAIS (obrigatório antes de qualquer slide)

> ⚠️ NUNCA pular esta etapa. O ângulo define TUDO: gancho, estrutura, tom.
> Propor sempre 3 ângulos diferentes. Esperar aprovação antes de continuar.

Para cada ângulo, especificar:
- **Gancho** — o que faz parar o scroll (dado, contraste, pergunta, provocação)
- **Estrutura narrativa** — como a história se desenvolve (lista, antes/depois, argumento, processo)
- **Tom** — emocional / racional / provocador / didático
- **Por que funciona para este cliente** — ancorar na voz e dados reais

```
ÂNGULO A — [nome do ângulo]
Gancho: [primeira linha que para o scroll]
Estrutura: [como o carrossel se desenvolve]
Tom: [emocional / racional / provocador / didático]
Por que funciona: [razão específica para este cliente]

ÂNGULO B — [nome do ângulo]
...

ÂNGULO C — [nome do ângulo]
...
```

### Etapa 3 — VISUAL TEARDOWN *(só se houver referência visual)*

Se o cliente forneceu um print de referência, analisar em 5 pontos antes de continuar:
- **Layout & grid** — como os elementos estão dispostos no slide
- **Tipografia** — serif / sans / display, pesos, hierarquia de tamanho
- **Paleta** — hex codes se legíveis, ou descrição precisa
- **Densidade** — minimal / médio / denso
- **Mood** — editorial, caloroso, urgente, clínico, etc.

Esta análise define o sistema visual de TODOS os slides do carrossel.

### Etapa 4 — DECISÃO DE SLIDES (após aprovação do ângulo)

Decidir contagem com base no que o conteúdo realmente precisa — nunca encher por encher:

| Tipo de conteúdo | Slides |
|-----------------|--------|
| Insight único, citação, ponto de virada | 5–6 |
| Lista, how-to, tutorial, passo a passo | 7–8 |
| Deep-dive, arco de história, argumento complexo | 9–10 |

Máximo absoluto: **10 slides**. Nunca mais.

### Etapa 5 — ARCO DE SLIDES

```
Slide 1         → Hook (capa — o motivo de deslizar)
Slide 2         → Contexto ou setup do problema
Slides do meio  → Pontos, passos ou beats da história (variável)
Penúltimo       → Recap, insight ou payoff
Último          → CTA (seguir, salvar, comentar, DM, link)
```

### Etapa 6 — OUTPUT POR SLIDE

Para cada slide, entregar:

```
Slide [N] — [nome do beat]
- Headline: [texto final — não placeholder]
- Body: [texto final ou "sem body"]
- Visual direction: [1–2 frases. Descrever como cinematógrafo: sujeito + ambiente + iluminação + composição + onde o texto vive]
```

**Regras de visual direction:**
- Pensar como cinematógrafo, não como copywriter
- Ruim: "pessoa trabalhando no laptop"
- Bom: "sujeito filmado por trás, sentado à mesa de madeira junto à janela no golden hour, luz direcional quente rasgando a cena, enquadramento no terço inferior deixando espaço limpo acima para o headline"
- Uma cena → um ambiente → um sentimento — sem metáforas engenhosas
- Todo visual deve ter espaço negativo natural para o texto viver
- Indicar onde na frame o texto se posiciona

### Etapa 7 — HANDOFF PARA VISUAL SYSTEM

Após aprovação do arco de slides e copy:
→ Passar para `visual-system.md` para gerar o JSON de imagem por slide
→ O JSON usa o sistema visual do cliente (paleta, fontes, grupos visuais) + a visual direction de cada slide
